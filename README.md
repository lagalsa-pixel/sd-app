**Локальное настольное приложение с двумя ИИ-инструментами:**

1. **🎨 SD Image Generator** — генерация изображений через Stable Diffusion
   (полностью офлайн после первой загрузки моделей).

2. **📡 GPON FTTH Planner** — планирование оптической сети FTTH для сельских
   населённых пунктов на основе алгоритма
   [`gpon-ftth-planner`](https://github.com/lagalsa-pixel/gpon-ftth-planner) v1.1,
   **оптимизированного для CPU**, с **отрисовкой карты сети** на спутниковой
   мозаике Google Satellite z18.

## Возможности

### 🎨 SD Image Generator

- **Текст → изображение** и **Изображение → изображение** режимы
- **Русский интерфейс + авто-перевод промптов** (локальная модель)
- **Полностью офлайн** после первой загрузки моделей
- **CPU/GPU**: работает на любом железе (медленнее на CPU)
- Управление памятью, сохранение в PNG/JPEG/WEBP

### 📡 GPON FTTH Planner

Алгоритм `gpon-ftth-planner` v1.1 — проектирование оптической сети
GPON для сёл с расчётом оптического бюджета и ведомости материалов.
Реализован в оптимизированной для CPU версии:

- **Векторизация** через NumPy/SciPy (вместо Python-циклов)
- **Sparse CSR-матрицы** для дорожного графа
- **KDTree** для O(log n) поиска ближайших узлов
- **Один вызов Dijkstra** (вместо K вызовов) — ускорение в K раз
- **Float32** для экономии памяти на больших графах
- **Кэширование OSM** на диске (повторный запуск быстрее)
- **🗺 Отрисовка карты сети** на спутниковой мозаике Google Satellite z18
  со слоями: зоны (выпуклые оболочки), дропы, ствол, фидеры (пунктир),
  муфты, ДХ, зонные ОРШ, ЦУ + легенда с авто-размещением по минимуму
  перекрытий + масштабная линейка + стрелка севера

**Стадии алгоритма:**

1. `fetch` — загрузка OSM-данных (дороги + здания) по координатам села
2. `households` — детекция домохозяйств (OSM-здания + кластеризация усадеб)
3. `anchor` — выбор здания-ЦУ (центральной узловой точки) через скоринг
4. `network` — построение сети: дорожный граф → MST → SPT → муфты → дропы
5. `boq` — расчёт материалов:
   - **Схема A** (централизованная): сплиттеры 1:64 в ЦУ
   - **Схема D** (зонные ОРШ, рекомендуется): жадное разбиение по S_MIN
6. `optical_budget` — расчёт затухания худшей линии каждой зоны (Class B+/C+)

**Что НЕ входит (по сравнению с оригиналом):**

- CV-детекция крыш (требует OpenCV + спутниковые тайлы)
- VLM-верификация кандидатов (требует внешнего API)
- SIFT-привязка пользовательского кадра
- Рендеринг карты зон (только текстовый отчёт)

Это снижает точность для сёл с дефицитом OSM-разметки, но даёт сеть
и BoQ, приемлемые для предварительной оценки.

## 🔄 Автообновление зависимостей

Приложение **автоматически проверяет и обновляет зависимости** при каждом
запуске (через модуль `updater.py`).

### Что происходит при запуске

1. **Шаг 1: критичные пакеты** (`Pillow`, `numpy`, `scipy`, `requests`)
   - Если отсутствуют — устанавливаются **автоматически без вопросов**
   - После установки приложение просит перезапуск

2. **Шаг 2: SD-пакеты** (`torch`, `torchvision`, `diffusers`,
   `transformers`, `accelerate`)
   - Если отсутствуют — показывается диалог с описанием
   - Пользователь может:
     - согласиться → установка ~2 ГБ, потом перезапуск
     - отказаться → GPON-планировщик продолжит работать без SD

### Как это работает

- `updater.py` парсит `requirements.txt` и проверяет установленные
  версии через `importlib.metadata`
- При несоответствии запускает `pip install -r requirements.txt`
- Выводит прогресс в консоль и лог
- Не трогает пакеты, которые соответствуют требованиям

### Запуск проверки вручную

```bash
# Только проверить, не устанавливать
python updater.py --check-only --no-sd

# Проверить всё (включая SD)
python updater.py --check-only

# Установить недостающее
python updater.py
```

### Если автообновление не работает

Возможные причины:
- Нет интернета → `pip install` не сможет скачать пакеты
- `pip` не установлен → установите через `python -m ensurepip --upgrade`
- Нет прав на запись → запустите CMD от администратора

Вручную:
```bash
pip install -r requirements.txt
```

## Использование GPON FTTH Planner

### Запуск планирования

1. Перейдите на вкладку **"📡 GPON FTTH Planner"**.
2. Заполните форму слева:
   - **Имя села** — латиницей (например, `bobrovka`)
   - **Широта, Долгота** — координаты центра села
     (можно получить с OSM: правый клик на карте → координаты;
     или с Google Maps: правый клик → координаты)
   - **Ожидаемое число ДХ** — для контроля (из тендерных данных)
   - **Радиус поиска** — типично 2500 м, для крупных сёл увеличить
   - **Тип зоны:** bbox (авто-граница по застройке) или radius (фикс.)
   - **S_MIN** — порог окупаемости зонного ОРШ (по умолчанию 15 вол-км)
   - **MIN_ZONE** — мин. ДХ в зоне (по умолчанию 48 = заполнение 75%)
3. Нажмите **"🚀 Запустить планирование"**.
4. Дождитесь завершения — в правой панели появится отчёт.

### Что вы получите в отчёте

- **Село:** координаты, радиус поиска
- **Домохозяйства:** найдено vs заказ, отклонение
- **ЦУ:** id OSM-здания, площадь, score
- **Сеть:** обслужено ДХ, муфты, км магистрали/дропов
- **BoQ схема A:** волокно-км, кабель-км, сплиттеры, сварки, муфты
- **BoQ схема D:** то же + число зон, экономия волокно-км vs A
- **Оптический бюджет (Class B+):** худшая линия, маржа, статус
- **Зоны (детально):** для каждой — ДХ, длина L, затухание, маржа, статус

### Статусы оптического бюджета

- **ok** — зона годна, маржа ≥ 3 дБ (полная годность, оптика Class B+)
- **ok-hard** — годна, но запас < 3 дБ → рекомендация Class C+ или 1:32
- **EXCEEDED** — превышение 28 дБ → редизайн зоны (сдвиг ОРШ / 1:32)

### Кэш OSM

При первом запуске для каждого села скачиваются OSM-данные
(дороги + здания) и кэшируются в `gpon_work/osm_raw/`. При повторных
запусках того же села (даже с другими параметрами) — интернет не нужен.
Кнопка **"⏹ Очистить кэш OSM"** удаляет кэш.

### Сохранение отчёта

Кнопка **"💾 Сохранить отчёт (JSON)..."** — сохраняет полный результат
(включая координаты муфт, дропов, фидерных рёбер) в JSON. Можно
использовать для дальнейшей обработки в GIS, QGIS, Google Earth и т.д.

### 🗺 Отрисовка карты сети

После планирования приложение может автоматически отрисовать карту сети
на спутниковой мозаике. Включается чекбоксами в левой панели:

- **"🗺 Отрисовать карту сети (спутник + слои)"** — основной переключатель
- **"📥 Скачать спутниковые тайлы Google z18"** — если включено,
  скачиваются тайлы Google Satellite (мозаика ~0.38 м/px на 50° с.ш.);
  если выключено — карта рисуется на сером фоне (только слои сети)

**Что отрисовывается на карте:**

| Слой | Цвет | Описание |
|------|------|----------|
| Зоны (выпуклые оболочки) | Полупрозрачный цвет зоны | Окрашивание территорий каждой зоны |
| Дропы | Жёлтый | Дроп-кабели от муфт к домохозяйствам |
| Ствол сети | Серо-белый | Магистральные кабели зоны ЦУ |
| Распределительная сеть | Цвет зоны | Кабели внутри каждой зоны |
| Фидеры ЦУ→ОРШ | Пунктир цвета зоны | Кратчайшие трассы фидерных волокон |
| Муфты | Бирюзовый квадрат | Точки ветвления оптического кабеля |
| Домохозяйства | Цвет зоны | Маркеры ДХ (цвет = зона обслуживания) |
| Зонные ОРШ | Шкаф с номером зоны | Уличные шкафы со сплиттерами 1:64 |
| ЦУ (OLT) | Красное здание + антенна | Центральный узел: станция OLT |

**Дополнительно:**

- **Шапка со статистикой:** название села, схема D, спутник, ДХ, зоны,
  волокно-км, кабель-км, сплиттеры
- **Легенда** с авто-размещением: 5 позиций (BL/BR/ML/MR/TL) по минимуму
  взвешенного перекрытия с элементами сети
- **Масштабная линейка** — выбирается из [100, 200, 500, 1000, 2000] м
  так, чтобы помещалась в правом нижнем углу
- **Стрелка севера** — в правом верхнем углу

**Файлы карты:**

| Файл | Размер | Назначение |
|------|--------|-----------|
| `gpon_work/maps/<key>_зоны_ОРШ.jpg` | ~5–30 МБ | Полное разрешение (q90) |
| `gpon_work/maps/<key>_preview.png` | ~1–6 МБ | Превью 1800px для UI |

**Время работы:**

- Без скачивания тайлов: +2–5 сек к планированию
- Со скачиванием тайлов: +30–120 сек (зависит от площади села и интернета)
- Тайлы кэшируются в `gpon_work/tiles/g18/` — повторный запуск быстрее

**Превью в UI:**

После завершения планирования автоматически открывается вкладка **"🗺 Карта"**
с превью. Доступны кнопки:
- **"📂 Открыть карту (JPG)"** — открыть полное разрешение во внешнем

- **"🖼 Открыть превью"** — открыть PNG превью
- **"💾 Сохранить карту как..."** — сохранить в выбранное место

## Оптимизации для CPU (как это работает)

Оригинальный `ftth_pipeline.py` из репозитория
`lagalsa-pixel/gpon-ftth-planner` рассчитан на полную обработку
(включая CV-детекцию крыш и VLM-верификацию), что требует GPU и
больших объёмов ОЗУ. Реализация в `gpon_planner.py` переписана с упором
на CPU:

### Ключевые оптимизации

1. **Один вызов Dijkstra для всех терминалов.** Оригинал вызывает
   `scipy.sparse.csgraph.dijkstra(C, indices=[terminals], ...)` для
   каждого терминала отдельно (K вызовов). В оптимизированной версии —
   один вызов со списком всех терминалов (`indices=terminals`),
   что даёт ускорение в K раз (для типичного села K=100–500).

2. **Векторизованная детекция границы села.** Оригинал использует
   Python-циклы для дилатации и поиска связных компонент. Оптимизированная
   версия — `scipy.ndimage.binary_dilation` с круглым ядром и
   `scipy.ndimage.label`, что работает в ~10–50 раз быстрее.

3. **KDTree для O(log n) поиска.** Привязка домохозяйств к дорожному
   графу через `scipy.spatial.cKDTree.query` — O(log n) на запрос,
   вместо O(n) у brute-force. KDTree также используется для проверки
   "близости к дороге".

4. **CSR-матрицы (scipy.sparse.csr_matrix).** Дорожный граф хранится
   в разреженном формате — Dijkstra работает за O(E log V) вместо O(V²).

5. **Float32 вместо float64.** Узлы графа и матрица расстояний —
   в `np.float32`, что экономит 50% памяти и улучшает cache locality.

6. **Кэш OSM на диске.** После первой загрузки села повторные запуски
   не требуют интернета. Кэш хранится в `gpon_work/osm_raw/*.xml`.

### Что НЕ оптимизировано (намеренно)

- **Сами алгоритмы** (MST, SPT, жадное разбиение) оставлены как в
  оригинале — это гарантирует совместимость результатов.
- **Формулы BoQ и оптического бюджета** — идентичны оригиналу
  (§VI и §VII `ALGORITHM_FTTH.md` v1.1).
- **Параметры по умолчанию** — те же, что в оригинальном DEFAULTS.

## Решение проблем

### GPON: "Не найдено ни одного домохозяйства"
→ В OSM нет разметки зданий в этом районе. Попробуйте:
   - другое село (с большей OSM-разметкой);
   - увеличить радиус поиска;
   - проверить координаты (должны быть в десятичных градусах: 50.1234, 82.5678).

### GPON: "bbox слишком велик для OSM API"
→ Уменьшите радиус поиска (OSM API имеет лимит ~50 000 объектов на запрос).

### GPON: очень медленно
→ Это нормально для больших сёл (1000+ ДХ). Типичное время:
   - 100 ДХ: 5–15 сек
   - 500 ДХ: 30–90 сек
   - 1000+ ДХ: 2–5 мин
   Кэш OSM ускоряет повторные запуски.

### GPON: "ModuleNotFoundError: scipy"
→ Запустите `install.bat` ещё раз. Если не помогает — вручную:
   ```
   .venv\Scripts\activate
   pip install scipy numpy requests
   ```

### GPON: "EXCEEDED" в оптическом бюджете
→ Зона требует редизайна:
   - увеличьте `MIN_ZONE` (зоны станут крупнее, ОРШ ближе к центру);
   - используйте сплиттер 1:32 (замените `split_ratio: 64` → `32` в коде);
   - или Class C+ оптику (`ob_budget_db: 32`).

### GPON: карта не отрисовалась
→ Возможные причины:
   - выключен чекбокс "Отрисовать карту сети";
   - нет интернета для скачивания тайлов (выключите "Скачать спутниковые
     тайлы" — карта отрисуется на сером фоне);
   - `Pillow` не установлен (`pip install Pillow`);
   - очень большая мозаика (>9000×9000px) — Pillow выдаёт
     DecompressionBombWarning, но карта сохраняется.

### GPON: "DecompressionBombWarning"
→ Это предупреждение Pillow при работе с большими изображениями
   (>89 Мп). Карта всё равно сохраняется корректно. Если мешает —
   уменьшите `radius_m` для меньшей области.

### SD: общие проблемы
→ См. раздел "Решение проблем" в `app.log`.
